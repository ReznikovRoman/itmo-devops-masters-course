# Практика: проектируем пайплайн

## Описание

> В сервис `delivery-demo` добавили новую функциональность: эндпоинт `/discount`
> с проверкой, что процент скидки лежит в диапазоне от 0 до 100.
> Ветка: `feature/discount-validation`.

## Условия релиза

- Образ должен однозначно связываться с коммитом: по тегу можно понять, из какого кода он собран.
- В реестр попадает только то, что прошло статический анализ и тесты.
- Прямой push в `main` запрещён - изменения идут только через pull request.
- Проверка в pull request должна укладываться примерно в 5 минут (ограничение скорости сборки).
- Зависимости задаются в `requirements.txt` и должны ставиться воспроизводимо.

## Опрос

Для каждой ошибки выберите проверку, которая поймает её **первой**:

| Ошибка из истории | Варианты |
|---|---|
| А. В `main` появился конфликт | линтер / проверка актуальности ветки при merge / тесты / сборка образа / ревью человеком |
| Б. CI собрал образ с устаревшей зависимостью | линтер / тесты / сборка образа в PR / проверка тега / ревью человеком |
| В. Команда не поняла, какой файл запускать | линтер / `make`-команды и `CMD` в Dockerfile / тесты / сборка образа / ревью человеком |
